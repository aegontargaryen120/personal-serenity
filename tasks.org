* An overview of the process
- Scanner: Converts the source code into a list of meaningful tokens.
- Parser: Converts the tokens into a data structure called AST.
- Evaluator (Interpreted): Traverses the AST and evaluates it to a result.
- Code Generator (Compiled): Traverses the AST and converts it to assembly code, which it saves as a .s file.

  - bootstrap/code_generator.srn (2666 lines) exposes cgen(program) -> assembly

* DONE 2026-09-19 Metaprogramming: `shellex` + `file` file-writing         :stdlib:interpreter
  - Goal: `shellex("<cmd>")` runs a shell command and returns its exit code;
    `let f = "<path>"; file(f); f.write(text); f.close();` opens a file for
    writing, `.write()` appends the text plus a newline, and `.close()` flushes
    and saves. These are interpreter-only builtins for now.
- Design decisions:
  - `.` was previously a scan error (`let f = 2.5;`). It is now a DOT token.
    Appended AFTER EOF in the TokenType enum (type 44) so all existing token IDs
    (EOF=43, etc.) stay stable; bootstrap/scanner.srn mirrors the 1-based IDs.
  - New `MethodCall(receiver, method, arguments)` AST node + parser support:
    receiver.<method>(args) is accepted for an identifier receiver only, no
    chaining or arbitrary-expression receivers.
  - `file(path)` opens the handle for writing and creates missing parent
    directories. When the argument is a bare `Identifier`, the variable itself
    is REBOUND to the handle (so `let f = "x"; file(f); f.write(..)` works);
    it also returns the handle, so `let g = file("x"); g.write(..)` works too.
  - `shellex` uses subprocess.run(shell=True, capture_output=True, text=True),
    replays stdout+stderr to the program's own stdout (StringIO harnesses
    capture it) and returns the return code.
  - `f.write(text)` calls `str(_display(text))` then appends `'\n'`; handles
    render as `<file: {path}>` in output.
  - Both are host-side only. The compiled code generator raises clear
    CompileError text for `shellex`/`file` and for any MethodCall; the
    bootstrap evaluator reports them as interpreter-only runtime errors.
